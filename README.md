# 3DAndEngine — High-Performance AAA Microkernel Framework (v2.0.0)

![CI](https://github.com)
[![Language](https://shields.io)](https://cppreference.com)
[![License](https://shields.io)](LICENSE)

Высокопроизводительное, отказоустойчивое микроядро на стандарте **C++20**, спроектированное по принципам **Data-Oriented Design (DOD)**. Движок полностью изолирован от тяжелых ООП-абстракций, рантайм-аллокаций памяти и блокирующих примитивов синхронизации, обеспечивая бескомпромиссную скорость обработки данных (AAA-стандарт).

---

## 🔄 Эволюция архитектуры: В чём разница между v0.1.0 и v0.2.0?

В версии **v0.2.0** кодовая база пережила полную архитектурную революцию, перейдя от классической объектно-ориентированной модели (ООП) к парадигме управления данными.

| Архитектурный слой | Старая версия (v0.1.0) | Новая AAA-версия (v0.2.0) | В чём профит для скорости (Performance)? |
| :--- | :--- | :--- | :--- |
| **Парадигма ядра** | **Service Locator (ООП)**. Модули жестко связаны через интерфейсы, наследование и `std::shared_ptr`. | **Data-Driven (DOD)**. Полная слепота модулей. Взаимодействие происходит «вслепую» через единый ECS-реестр. | **Нулевая связанность (Zero Coupling)**. Модули графики, физики и инпута делятся только сырыми структурами данных. |
| **Менеджмент данных** | Разрозненные объекты в куче (Heap), связанные указателями. | **Cache-Friendly Sparse Set ECS**. Компоненты упакованы в непрерывные и плотные массивы (Dense Vectors). | **Zero CPU Cache Misses**. Процессор считывает компоненты пачками прямо в L1/L2 кэш, утилизируя SIMD-оптимизации. |
| **Шина событий** | Посимвольное сравнение строк (`std::string` топики) и синхронные колбэки. | **Lock-Free EventBus** на базе атомарных кольцевых буферов (Ring Buffers). | **1 такт CPU**. Строки хэшируются на этапе компиляции в `uint32_t` через `constexpr`. События не вызывают дедлоков. |
| **Многопоточность** | Классический пул потоков под тяжелыми мьютексами (`std::mutex`). | **Lock-Free JobSystem**. Задачи фиксированного размера (64 байта) под кэш-линию CPU. | **Zero Lock Contention**. Потоки общаются через `std::atomic` без блокировок, утилизируя `std::this_thread::yield()`. |
| **Управление памятью** | Постоянные скрытые аллокации в рантайме из-за `std::function` и строк. | **Zero Runtime Allocations**. Вся память под сущности, задачи и события выделяется пулами заранее. | **Отсутствие фризов**. Куча (Heap) во время игрового цикла не трогается, гарантируя стабильный Frame Time (60-120+ Гц). |

## 🛠 Ключевые компоненты микроядра

1. **`Types.h`**: Компиляционный хэш строк FNV-1a. Литерал `"topic/name"_id` вычисляется полностью на этапе сборки.
2. **`EcsRegistry.h`**: Быстрый реестр сущностей. Метод удаления использует алгоритм Swap-and-Pop, сохраняя плотность памяти.
3. **`EventBus.h`**: Атомарный буфер обмена пакетами (`EventPacket`), защищенный от race conditions.
4. **`JobSystem.h`**: Высокопоточный планировщик без lock-contention, убирающий накладные расходы планирования ОС.
5. **`PluginContract.h` & `PluginLoader.h`**: Строгий кроссплатформенный бинарный контракт (`extern "C"`), защищающий от проблем ABI компиляторов и позволяющий безопасно выгружать модули.

## 🚀 Как это работает («Слепое» взаимодействие плагинов)

В версии v0.2.0 плагины вообще ничего не знают о существовании друг друга. Они знают только о структурах компонентов.

```cpp
// 1. Плагин Ввода (InputPlugin) ловит нажатие клавиши и вешает скорость на ID игрока:
void InputUpdate(float dt) {
    auto* move = ctx.ecs->getComponent<MovementComponent>(player_entity);
    if (move) { move->vx = 10.0f; } // Просто пишем в память пула
    ctx.event_bus->broadcast("player/moved"_id); // Стреляем быстрым ID в шину
}

// 2. Плагин Физики (PhysicsPlugin) понятия не имеет об Инпуте, клавиатуре или сети. 
// Он просто линейно бежит по плотному массиву скоростей:
void PhysicsUpdate(float dt) {
    auto* pool = ctx.ecs->view<MovementComponent>();
    for (size_t i = 0; i < pool->data.size(); ++i) {
        Entity entity = pool->dense_to_entity[i];
        auto& move = pool->data[i];
        
        auto* transform = ctx.ecs->getComponent<TransformComponent>(entity);
        if (transform) { transform->x += move.vx * dt; }
    }
}
```

## 🔨 Сборка и Требования

* **Компилятор**: Строго с поддержкой **C++20** (MSVC v143+, GCC 11+, Clang 13+).
* **Система сборки**: CMake 3.20+
* **Пакетный менеджер**: vcpkg (манифестный режим через `vcpkg.json`).

### Локальная сборка:
```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

## ⚙️ Автоматизация CI/CD (GitHub Actions)
В проект встроен современный кроссплатформенный пайплайн автоматизации:
* **Интеграция**: Сборка тестируется на **Windows, Ubuntu и macOS** одновременно.
* **Встроенный контроль скорости**: Перед запуском ядра автоматически прогоняется встроенный пакет юнит-тестов (`src/UnitTestsMain.cpp`). Если тесты падают или ломается скорость — сборка в CI блокируется.
* **SDK Дистрибуция**: При публикации релиза пайплайн автоматически очищает бинарный мусор (`.obj`, `.ilk`) и упаковывает чистые заголовочные интерфейсы ядра вместе с исполняемыми файлами в ZIP-архивы для разработчиков плагинов.
